# Plan — git-better v1

**Date:** 2026-08-05   **Status:** Approved   **Spec:** docs/toolu/specs/v1.md   **Topic:** Ship `gb conventions`, `gb skill install`, and the release pipeline as 1.0.0.

## Context

`gb` implements pillar 1 of its own protocol (lean reads) and none of pillar 2:
the convention profile only exists as a bash + `jq` script inside the `toolu`
plugin. The binary is also undistributable — no release workflow, unpublished,
and carrying an unused `tokio` dependency. v1 lands `gb conventions`,
`gb skill install`, and a tag-driven release, then bumps to `1.0.0`.

AC-1…AC-7 below refer to the numbered acceptance criteria in the spec.

## Approach

Port the shim's detection rules into Rust with no `jq` and no network by
default. New `src/conventions/` module owns the profile: `hash.rs` (FNV-1a 64),
`mod.rs` (serde types), `detect.rs` (git + filesystem detection), `cache.rs`
(freshness, atomic write, prose merge). Reuse what exists rather than inventing:

- `src/git/proc.rs::run_git` for every git shell-out, with `-C <root>` so the
  detectors do not depend on the process cwd.
- `src/output/better.rs::{envelope_with_hints, error_envelope}` for `--better`.
- `src/output/theme.rs::Theme` + `src/output/layout.rs::pad_right` for the
  summary printer, which lands in its own `src/output/conventions_view.rs`
  because `human.rs` is at 435 of its 500-line ceiling.
- `tests/common/mod.rs` helpers (`init_repo`, `make_commit`, `make_branch`) to
  build real repositories for tests; no mock data anywhere.

`gb skill install` embeds `SKILL.md` with `include_str!` and writes it to
per-agent paths: whole-file for skill-shaped targets, marker-fenced blocks for
shared instruction files. Detection gates the default target set so an install
never fabricates an `AGENTS.md`.

Execution note: this session runs steps inline in the main thread rather than
through subagents (agent delegation is off for this session), so every step
declares `model: inherit`.

## Steps

1. **Dependencies and version** — drop `tokio`, add `time` with `formatting`,
   set `version = "1.0.0"`. (AC-5)
2. **Conventions core** — `src/conventions/{hash,mod,detect,cache}.rs`, declared
   in `src/lib.rs`. Detection per spec, including the zero-commit and
   no-branches paths; cache validates `schema_version`/`repo_root` and degrades
   to compute-and-print on any I/O failure. Unit tests for the majority
   threshold, type extraction, and FNV-1a stability.
3. **Conventions CLI** — `src/cli/conventions.rs` + `ConventionsArgs` in
   `src/cli/mod.rs`, `src/output/conventions_view.rs` for the five-line summary.
   Wires `--json` / `--better` / `--refresh` / `--with-remote` / `--save-prose`
   and rejects `--json --better`. (AC-2)
4. **Conventions integration tests** — `tests/cli_conventions.rs` against real
   temp repos, `GB_CACHE_DIR` redirected to a temp dir in every test, including
   the cache-hit mtime proxy and the `--save-prose` STDIN flow. (AC-3)
5. **Skill install** — `src/cli/skill.rs` with `print` / `path` / `install`,
   seven targets, fenced-block idempotency, foreign-content guard, `--dry-run`,
   and both report shapes (human lines and the `--better`
   `{installed, unchanged, skipped}` object).
6. **Skill tests** — `tests/cli_skill.rs` with `HOME` and repo both pointed at
   temp dirs so nothing touches the developer's real config. (AC-4)
7. **Release pipeline** — `.github/workflows/release.yml` (tag guard →
   `aarch64-apple-darwin` build → GitHub release → crates.io → tap bump, secrets
   gated at step level) and `packaging/homebrew/git-better.rb.tmpl`.
8. **Docs sync** — README (conventions, skill install, install channels, cache
   location), `SKILL.md` (pillar 2 + skill install), `AGENTS.md` (layout, cache
   path, 11-type detection note, revised out-of-scope list). (AC-7)
9. **Final gate** — `cargo fmt --check`, `cargo clippy --all-targets -- -D
   warnings`, `cargo nextest run`, release binary size, and
   `cargo package --list | grep SKILL.md`. (AC-1, AC-6)

## Critical files

Create:

```
src/conventions/mod.rs            Profile + nested types, SCHEMA_VERSION
src/conventions/hash.rs           FNV-1a 64 hex helper
src/conventions/detect.rs         repo_root, declared_files, source_hash, build_profile
src/conventions/cache.rs          cache_path, resolve (freshness + prose merge + atomic write)
src/cli/conventions.rs            arg validation, cache dispatch, three output shapes
src/cli/skill.rs                  targets, render, write, report
src/output/conventions_view.rs    five-line summary
tests/cli_conventions.rs          integration
tests/conventions_detect_unit.rs  detection + hash units
tests/cli_skill.rs                integration
.github/workflows/release.yml     tag → release → crates.io → tap
packaging/homebrew/git-better.rb.tmpl
```

`detect.rs` and `cli/skill.rs` are the two files at risk of growing; both stay
under the 500-line Rust ceiling, and if a detector or a target family pushes past
it the split (`detect/{commits,branches,files}.rs`) happens in that step, not
after a gate complaint. Detection returns `GbError`; the CLI surfaces it through
`anyhow` as the existing subcommands do, and cache I/O failures are swallowed by
design rather than propagated.

Modify: `Cargo.toml` (deps, version), `src/lib.rs` (`pub mod conventions`),
`src/cli/mod.rs` (`Conventions`, `Skill` variants before `Passthrough`),
`README.md`, `SKILL.md`, `AGENTS.md`.

## Verification

- Real-data path: every conventions test builds an actual repository with
  `tests/common::init_repo` and commits real conventional subjects
  (`feat(auth): … (#142)`), then asserts the detected profile. The
  unconventional case uses plain subjects in the same helper. No fixtures are
  hand-written JSON.
- Cache behavior is proven through the CLI with `GB_CACHE_DIR` in a temp dir:
  first call writes the file, second call leaves its mtime untouched and prints
  byte-identical output, `--refresh` bumps it.
- `--save-prose` is exercised by piping text on STDIN via `assert_cmd`'s
  `write_stdin`, then re-reading the profile to confirm `prose_pending` cleared.
- Skill tests set `HOME` to a temp dir, run `install --dry-run` and assert no
  file appeared, then install twice and assert the second run reports
  `unchanged` and that a fenced target contains exactly one marker pair.
- Self-check on this repo: `gb conventions --plain` must report
  `conventional-commits`, `scope used`, suffix `(#N)`, `type/kebab`, and
  `release.yml-workflow` after step 7.
- Gate: step `s9-gate`'s command, run before the PR opens.

## Deviations

- Ledger `check` filters use nextest's `binary(...)` predicate rather than
  `test(/regex/)`: `test()` matches test names, so the per-step filters matched
  nothing and nextest exited non-zero on "no tests to run".
- The release pipeline was rebuilt on the `Falconiere/comemory` pattern at the
  user's direction: release-plz (version + CHANGELOG + tag) fronting a
  dist-generated `release.yml` (build + GitHub Release + formula to the shared
  `Falconiere/homebrew-tap`), plus `release-finalize.yml` and `crates-io.yml`.
  This replaced the hand-rolled tag workflow and `packaging/homebrew/*.tmpl`,
  which are deleted. The tap push authenticates with the same GitHub App
  comemory uses instead of a PAT. `s7-release`'s check now validates the four
  release workflows plus `release-plz.toml` and `docs/release.md`.
