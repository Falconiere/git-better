# git-better v1 — design spec

**Date:** 2026-08-05   **Status:** Approved   **Topic:** `gb conventions`, `gb skill install`, and distribution as 1.0.0.

Supersedes the M2–M6 sketch in PR #1.

## Problem

`gb` ships pillar 1 of its own protocol (lean reads) and none of pillar 2.
`SKILL.md` promises agents a token-lean git companion that also removes
convention re-discovery cost, but the only implementation of that pillar is a
bash + `jq` script inside the `toolu` plugin. The Rust binary is also
undistributable: no release workflow, unpublished, and it carries a dependency
(`tokio`) that no code uses.

v1 closes the product story: both pillars in the binary, the protocol
installable into the agents that consume it, and a tagged, published artifact.

## Scope

| ID | Item |
| :-- | :-- |
| M3 | `gb conventions` — cached repo convention profile |
| M4 | `gb skill install` — write the protocol into agent config paths |
| M6 | Distribution — tagged GitHub release, crates.io, Homebrew tap |
| — | Drop the unused `tokio` dependency; bump version to `1.0.0` |

## Non-goals

- M2 write ops (`commit` / `push` / `rebase` / …) with `--better`. They already
  work through pass-through; a JSON envelope on a write returns almost no
  tokens. Deferred.
- MCP server (cut from v0.1, still cut).
- Cache compatibility with the bash shim in the `toolu` plugin. v1 owns its own
  cache location and does not try to keep the plugin's `PreToolUse` nudge
  reading the same file.
- Any target other than `aarch64-apple-darwin`.

## Compatibility contract

The CLI surface and the `--better` JSON envelope (with `schema_version` on the
conventions profile) are the stable contract for `1.x`. The Rust library API
(`git_better::*`) is internal and may change in any release.

## M3 — `gb conventions`

### Surface

```
gb conventions [--json] [--refresh] [--with-remote] [--save-prose <file>]
```

Plus the global `--better` / `--plain`.

| Flag | Behaviour |
| :-- | :-- |
| *(none)* | Five-line aligned summary; colored in a TTY, flat otherwise |
| `--json` | Raw profile JSON, no envelope (for `jq` pipelines) |
| `--better` | `{ok, command, data: <profile>, hints, meta}` envelope |
| `--refresh` | Recompute, ignoring cache freshness |
| `--with-remote` | Allow one bounded `gh pr list` call. Off by default |
| `--save-prose <file>` | Read distilled rules from STDIN, cache them against the file's content hash |

`--json` and `--better` together is an error (two mutually exclusive JSON
shapes). `--save-prose` with empty STDIN is an error.

### Profile schema (`schema_version: 1`)

```json
{
  "schema_version": 1,
  "repo_root": "/abs/path",
  "generated_at": "2026-08-05T12:00:00Z",
  "source_hash": "fnv1a64-hex",
  "commit_format": {
    "convention": "conventional-commits" | "unknown",
    "types": ["chore", "feat", "fix"],
    "scope": "used" | "none",
    "pr_suffix": "(#N)" | null,
    "samples": ["…", "…", "…"]
  },
  "branch_naming": { "pattern": "type/kebab" | "unknown", "prefixes": [], "examples": [] },
  "pr": { "template_path": null, "title_format": "conventional-commits", "body_sections": [], "recent_titles": [] },
  "release": { "tooling": [], "version_commit": null, "changelog": null },
  "issues": { "bug_template_path": null, "required_fields": [] },
  "prose_pending": ["CONTRIBUTING.md"],
  "prose_distilled": { "CONTRIBUTING.md": { "hash": "…", "rules": "…" } },
  "gh_available": false,
  "remote_consulted": false
}
```

`gh_available` means the `gh` binary is on `PATH`. `remote_consulted` means a
remote lookup actually ran — the two are independent, and hints key off
`remote_consulted`.

### Detection rules

Local git and filesystem only; no network unless `--with-remote`.

- **Subjects window**: `git log -n 50 --format=%s`. 50, not 100 — the profile
  must track the repo's *current* practice, and a wider window dilutes a
  recently adopted convention.
- **Convention**: subject matches
  `^(feat|fix|chore|docs|test|refactor|perf|build|ci|style|revert)(\([^)]+\))?!?: `.
  `conventional-commits` when matches are a majority of non-empty subjects,
  else `unknown`. The 11-type set here is *format detection* and is
  deliberately wider than the 9 types `output/icons.rs` renders tags for.
- **types**: sorted unique captured types. **scope**: `used` if any subject
  carries `(scope)`. **pr_suffix**: `(#N)` if any subject ends in ` (#123)`.
  **samples**: first 3 subjects.
- **Branches**: `git branch -a --format=%(refname:short)`, `origin/` stripped,
  `HEAD` and empties dropped, unique. `type/kebab` when a majority match
  `^[a-z]+/`. Prefixes unique; 2 examples.
- **PR**: `.github/PULL_REQUEST_TEMPLATE.md` or `.github/pull_request_template.md`;
  `body_sections` = text of `^#{1,3} ` headings. `title_format` mirrors
  `commit_format.convention`.
- **Release**: `release.yml-workflow` (`.github/workflows/release.yml`),
  `release-please` (`release-please-config.json` /
  `.release-please-manifest.json`), `semantic-release` (`.releaserc*` or
  `"semantic-release"` in `package.json`). `version_commit` =
  `chore(release): vX` when subjects show it. `changelog` = `CHANGELOG.md`.
- **Issues**: first case-insensitive `*bug*` file under `.github/ISSUE_TEMPLATE/`.
- **Prose**: `CONTRIBUTING.md` is the only pending candidate, and it is pending
  unless a distilled entry's hash equals the file's current content hash.
  `--save-prose` accepts any file under the repo root; entries for files that
  are not pending candidates are stored and carried forward but never surface in
  `prose_pending`.
- **`--with-remote`**: `gh pr list --limit 10 --json title`, 5 s wall clock,
  failure is non-fatal (`recent_titles: []`).

### Failure modes

| Case | Behaviour |
| :-- | :-- |
| Not a git repository | `GbError::NotARepository`, exit non-zero |
| Repository with zero commits | `git log` fails; treat as no subjects — `convention: unknown`, `types: []`, `samples: []`, `pr_suffix: null`. Never fatal |
| Repository with only a detached HEAD / no branches | `pattern: unknown`, empty prefixes and examples |
| Declared file unreadable mid-scan | that file contributes nothing to `source_hash`; detection continues |
| Cache unreadable, corrupt, wrong `schema_version`, or `repo_root` mismatch | treat as a miss, recompute, overwrite |
| Cache directory not writable | compute and print; never fail the command |
| `gh` missing or slow with `--with-remote` | `recent_titles: []`, `remote_consulted: true`, `gh_available` reflects the binary |
| `--save-prose` on a path that does not exist under the repo root | error, exit non-zero, cache untouched |
| `--save-prose` with STDIN attached to a TTY, or empty STDIN | error asking for piped text; cache untouched |
| `--json` together with `--better` | error naming the conflict |

### Cache

- Directory: `$GB_CACHE_DIR`, else `$XDG_CACHE_HOME/git-better`, else
  `$HOME/.cache/git-better`. File: `conventions/<fnv1a64(repo_root)>.json`.
- Reuse the cached profile iff it parses, carries `schema_version: 1`, has a
  matching `repo_root`, its `source_hash` matches the current declared-file
  hash, and the file is ≤ 7 days old — and neither `--refresh` nor
  `--save-prose` was passed.
- Accepted limitation: `source_hash` covers declared *files* only, so a repo
  that changes commit style without touching a convention file keeps serving the
  old profile until the 7-day mtime backstop expires. `--refresh` is the escape
  hatch, and the human summary is cheap enough to re-run.
- `prose_distilled` rules are stored truncated to 8 KB per file so a long
  distillation cannot bloat `--better` output.
- `source_hash` = FNV-1a-64 over the concatenated contents of the declared
  convention files in sorted path order (PR templates, `CONTRIBUTING.md`,
  `.czrc`, `cz.json`, `.releaserc*`, `release-please-config.json`,
  `.github/release.yml`, `.gitmessage`, `CODEOWNERS`, `commitlint*`, issue
  templates). Non-cryptographic on purpose: this keys a cache, it does not
  authenticate anything.
- Writes are atomic (temp file + rename). Every cache failure degrades to
  compute-and-print; it never fails the command.
- Recompute merges the prior `prose_distilled` map forward.

### Human summary

```
commit:  conventional-commits | scope used | suffix (#N)
branch:  type/kebab [chore, ci, docs, feat, fix, style]
pr:      template none | sections []
release: [] | none
prose:   pending []
```

### Hints (`--better`)

- `prose_pending` non-empty → read the file once, then
  `gb conventions --save-prose <file>`.
- `convention: unknown` → no dominant convention; match `samples`.
- `remote_consulted: false` → re-run with `--with-remote` for recent PR titles.

## M4 — `gb skill install`

### Surface

```
gb skill print                 # embedded SKILL.md to stdout
gb skill path                  # resolved target paths, one per line
gb skill install [--target <t>]... [--all] [--dry-run] [--force]
```

`SKILL.md` is embedded at compile time (`include_str!`), so the binary is
self-sufficient.

### Targets

| Target | Path | Write style |
| :-- | :-- | :-- |
| `claude-user` | `$CLAUDE_CONFIG_DIR`\|`~/.claude`/`skills/git-better/SKILL.md` | whole file |
| `claude-project` | `<repo>/.claude/skills/git-better/SKILL.md` | whole file |
| `cursor` | `<repo>/.cursor/rules/git-better.mdc` | whole file + `alwaysApply` frontmatter |
| `windsurf` | `<repo>/.windsurf/rules/git-better.md` | whole file |
| `copilot` | `<repo>/.github/copilot-instructions.md` | fenced block |
| `codex` | `$CODEX_HOME`\|`~/.codex`/`AGENTS.md` | fenced block |
| `agents-md` | `<repo>/AGENTS.md` | fenced block |

Default (no `--target`, no `--all`): install only to targets whose detect rule is
satisfied — for directory-based targets the marker directory exists
(`~/.claude`, `<repo>/.cursor`, `<repo>/.github`, …); for shared-file targets
(`AGENTS.md`, `copilot-instructions.md`, `~/.codex/AGENTS.md`) the file itself
exists, so a default install never creates an `AGENTS.md` in a repo that has
none. `--all` and an explicit `--target` bypass the detect rule and create
missing parents. `--target` is repeatable, exact, and errors with the list of
valid names on an unknown value.

Outside a git repository, project-scoped targets are skipped with reason
`no repository`; user-scoped targets (`claude-user`, `codex`) still install.

Fenced blocks are delimited by `<!-- git-better:begin -->` /
`<!-- git-better:end -->` and replaced in place on re-install, so the command is
idempotent and never duplicates; a file with no markers gets the block appended.
Whole-file targets are rewritten only when the rendered content (frontmatter
included, for `cursor`) differs. `--force` rewrites regardless, and is also what
overrides the *foreign content* guard: a whole-file target whose existing text is
neither byte-identical nor recognizably ours (no `name: git-better`) is skipped
unless `--force` is given.

### Report

Human: one line per target — `wrote`, `unchanged`, `skipped (parent missing)`,
`skipped (foreign content, use --force)`. `--better`:
`{installed: [], unchanged: [], skipped: [{path, reason}]}`. `--dry-run` produces
the same report with no writes.

## M6 — Distribution

- Version `1.0.0`.
- `.github/workflows/release.yml`, on `push: tags: ['v*']` plus
  `workflow_dispatch`:
  1. **guard** — tag version must equal `Cargo.toml` `version`, else fail.
  2. **build** on `macos-14`: `cargo build --release --target aarch64-apple-darwin`,
     tarball + `.sha256`, attach to a GitHub release.
  3. **publish** — `cargo publish` (`CARGO_REGISTRY_TOKEN`).
  4. **tap** — render `packaging/homebrew/git-better.rb.tmpl` with the version
     and tarball sha, push to `Falconiere/homebrew-tap` (`HOMEBREW_TAP_TOKEN`).
- Steps 3 and 4 are skipped (not failed) when their secret is absent, so a
  first tag can produce a release before the accounts are wired. The `secrets`
  context is unavailable in a job-level `if:`, so each of those jobs copies its
  secret into `env` in a first step and gates the real step on
  `if: env.HAS_TOKEN == 'true'`.
- The release job needs `permissions: contents: write`; the tap job pushes with
  `HOMEBREW_TAP_TOKEN`, not `GITHUB_TOKEN`.

### Operator prerequisites (outside this repo)

1. Create `Falconiere/homebrew-tap`.
2. Add repo secrets `CARGO_REGISTRY_TOKEN` and `HOMEBREW_TAP_TOKEN`.
3. Confirm the crates.io name `git-better` is available or already owned — this
   is unverified and blocks only the publish step. Owner: repo owner.

## Layout

```
src/conventions/{mod,detect,cache,hash}.rs   profile types, detection, cache, FNV-1a
src/cli/{conventions,skill}.rs               arg handling + dispatch
src/output/conventions_view.rs               five-line summary printer
packaging/homebrew/git-better.rb.tmpl        tap formula template
.github/workflows/release.yml                tag → release → crates.io → tap
```

`output/human.rs` is at 435 of its 500-line ceiling, so the summary printer
gets its own file.

## Dependencies

- **Out**: `tokio` — declared since M0, referenced nowhere.
- **In**: `time` (`formatting` feature) for the RFC 3339 `generated_at` stamp.
  It is already in the build graph via `syntect → plist`, so this adds no
  compile or binary cost.
- **Not added**: any hashing crate. `source_hash` and prose hashes use an FNV-1a
  64 helper in `conventions/hash.rs` — a cache key needs determinism, not
  cryptography, and hand-rolling it is a dozen lines with a stable definition
  that will not drift with the toolchain.

## Tests

Real repositories built with `tests/common`; no mock data. Every conventions
test points `GB_CACHE_DIR` at a temp dir so the developer's real cache is never
touched.

- `tests/cli_conventions.rs` — conventional repo vs unconventional repo; scope
  and `(#N)` detection; PR-template sections; branch pattern; `--json` shape;
  `--better` envelope + hints; cache hit on second call; `--refresh`;
  `--save-prose` from STDIN clears `prose_pending`; `--json --better` rejected.
- `tests/conventions_detect_unit.rs` — majority threshold at the boundary,
  type extraction, FNV-1a stability.
- `tests/cli_skill.rs` — `skill print` matches the embedded text; `--dry-run`
  writes nothing; install then re-install reports `unchanged`; fenced-block
  replacement does not duplicate; foreign file is skipped without `--force`.

## Acceptance criteria

**AC-1:** `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, and
`cargo nextest run` are green; no test regressions from the 68 baseline.

**AC-2:** `gb conventions` on this repo reports `conventional-commits`,
`scope none`, suffix `none`, branch `type/kebab`, and lists
`release.yml-workflow` once the release workflow lands. (Verified against the
real history: 15 of 27 subjects in the window are conventional, none carry a
scope, none end in ` (#N)`. Scope and PR-suffix detection are covered instead by
the `init_with_pr_trail` fixture, whose subjects have both.)

**AC-3:** A second `gb conventions` run inside 7 days prints byte-identical
output and leaves the cache file's mtime unchanged (the externally observable
proxy for "no recompute"); `--refresh` updates the mtime.

**AC-4:** `gb skill install --dry-run` leaves the filesystem untouched; a real
install followed by a second install reports `unchanged` for every target.

**AC-5:** `tokio` is absent from `Cargo.toml` and `Cargo.lock`.

**AC-6:** Release binary stays under 25 MB, and `cargo package --list` includes
`SKILL.md` so the `include_str!` in `cli/skill.rs` survives a publish
verification build.

**AC-7:** README, SKILL.md, and AGENTS.md describe `conventions`,
`skill install`, the cache location, and the install channels.
